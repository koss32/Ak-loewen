# Vercel REST API (official docs, checked 2026-09-18)

- **Base URL:** `https://api.vercel.com`; all REST endpoints are under this HTTPS host. Auth is `Authorization: Bearer <TOKEN>`. Create/manage tokens at <https://vercel.com/account/tokens>. Official overview/index: <https://vercel.com/docs/rest-api> (the index catalogs the endpoint pages; it currently links the full REST catalog, including Projects, Deployments, Domains, Environment, Teams, etc.).
- **Token guidance:** Use an Access Token created in account settings. For least privilege, create a scoped token (scope it to the required team/resource and read-only permissions where offered); do not place token values in URLs or logs. Token settings URL: <https://vercel.com/account/tokens>. No secret is needed for this research.
- **Harmless auth test:** `GET https://api.vercel.com/v2/user` with `Authorization: Bearer <TOKEN>` (read-only identity check; 2xx confirms auth, 401 means missing/invalid token). Do not test with writes.
- **Projects list:** `GET https://api.vercel.com/v10/projects` — official page <https://vercel.com/docs/rest-api/projects/retrieve-a-list-of-projects>. It is paginated; `from` is a timestamp/continuation token and `limit` controls count. `teamId` or `slug` performs the request on behalf of a team; absent those, personal account scope applies. Other filters include `search`, repo fields, and `excludeRepos`.
- **Get project metadata:** `GET https://api.vercel.com/v9/projects/{idOrName}` — <https://vercel.com/docs/rest-api/projects/find-a-project-by-id-or-name>. Team context can be supplied with `teamId` or `slug` query parameters.
- **Project environment metadata:** `GET https://api.vercel.com/v10/projects/{idOrName}/env` — <https://vercel.com/docs/rest-api/projects/retrieve-the-environment-variables-of-a-project-by-id-or-name>; team context via `teamId`/`slug`, with documented filtering/query options. Sensitive environment variables cannot be decrypted once created (<https://vercel.com/docs/environment-variables/sensitive-environment-variables>); a read-only metadata call should not be treated as a secret-retrieval mechanism. The separate `GET /v1/projects/{idOrName}/env/{id}` page is explicitly “retrieve decrypted value” and should be excluded from a metadata-only connection.
- **Rate limits:** Responses expose `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset`; see <https://vercel.com/docs/limits#rate-limits> for plan/endpoint-specific limits. Respect 429/backoff and these headers; the REST overview does not give one universal numeric limit.
